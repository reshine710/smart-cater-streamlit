## 📊 API 限制總結

### 已知限制
| 參數 | 限制 | 說明 |
|------|------|------|
| `limit` | ≤ 1000 | 單次查詢最多返回 1000 筆 |
| `start_date` | 必需 | 格式: YYYY-MM-DD |
| `end_date` | 必需 | 格式: YYYY-MM-DD |
| `page` | 可選 | 用於分頁（預設 1） |
| `machine_id` | 可選 | 篩選特定機台 |

### 如何獲取超過 1000 筆數據

使用分頁機制：

```python
all_data = []
page = 1
limit = 1000

while True:
    batch = api.get_transactional_data(
        start_date, 
        end_date, 
        limit=limit,
        page=page
    )
    
    if not batch:
        break
    
    all_data.extend(batch)
    page += 1
    
    # 如果返回的數據少於 limit，表示沒有更多數據了
    if len(batch) < limit:
        break
```

## 🎓 學到的經驗

### 1. API 參數驗證
- 始終查看 API 文檔確認參數限制
- 不要假設 limit 可以設置為任意大的值
- 使用合理的默認值

### 2. 錯誤日誌的重要性
- 詳細的錯誤日誌能快速定位問題
- 422 錯誤通常包含有用的驗證信息
- 記錄完整的請求參數幫助調試

### 3. 測試與生產環境的差異
- 測試腳本使用小的 limit 值（10）成功
- 生產代碼使用大的 limit 值（2000）失敗
- 需要在實際環境中測試真實的參數

### 4. 分頁的重要性
- 對於大量數據，使用分頁是最佳實踐
- 避免一次性請求過多數據
- 提供更好的用戶體驗（漸進式載入）
