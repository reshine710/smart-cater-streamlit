# 前台獲取機台狀態資料流程說明

## 概述

本文檔說明前台如何從後端 API 獲取機台狀態資料，特別是錯誤碼的處理流程。

## 資料流程圖

```
後端 API
    ↓
GET /machines (返回機台列表，包含 status 欄位)
    ↓
utils.py: VendingMachineAPI.get_machines()
    ↓
modules/machine_status.py: machine_status_page()
    ↓
狀態映射與顯示
```

## 詳細流程

### 1. API 呼叫層（utils.py）

#### 1.1 獲取機台列表 - `get_machines()`

**位置**：`utils.py` 第 384-429 行

**API 端點**：`GET /machines`

**請求範例**：
```python
response = requests.get(
    f"{self.base_url}/machines",
    headers=self._get_auth_headers(),
    timeout=10
)
```

**回應格式**：
```json
[
    {
        "id": 1,
        "machine_code": "SC-NCU-001",
        "name": "測試機台 001",
        "status": "maintenance",  // 或 "error", "missing", "online", "offline"
        "location": {...},
        "last_online": "2024-01-01T12:00:00Z",
        "last_heartbeat": "2024-01-01T12:00:00Z",
        ...
    },
    ...
]
```

**或分頁格式**：
```json
{
    "items": [...],
    "total": 10
}
```

**處理邏輯**：
- 檢查回應狀態碼（200, 401, 500）
- 處理分頁格式（檢查是否有 `items` 欄位）
- 返回機台列表（List[Dict]）

#### 1.2 獲取單一機台詳情 - `get_machine_detail()`

**位置**：`utils.py` 第 432-460 行

**API 端點**：`GET /machines/{machine_id}`

**回應格式**：單一機台物件，包含完整的狀態資訊

### 2. 狀態處理層（modules/machine_status.py）

#### 2.1 頁面初始化 - `machine_status_page()`

**位置**：`modules/machine_status.py` 第 369-400 行

**流程**：
```python
# 1. 從 API 獲取機台列表
machines = st.session_state.api.get_machines()

# 2. 過濾有效機台（必須有 id）
valid_machines = []
for machine in machines:
    if isinstance(machine, dict) and machine.get('id'):
        valid_machines.append(machine)
```

#### 2.2 狀態映射邏輯

**位置**：多處，統一處理邏輯如下

**後端狀態 → 前台狀態映射**：

| 後端狀態 | 前台狀態 | 顯示文字 | 圖示 | 背景色 |
|---------|---------|---------|------|--------|
| `online` | `online` | 上線 | 🟢 | 淺綠色 (#d4edda) |
| `offline` | `offline` | 離線 | ⚪ | 淺灰色 (#e2e3e5) |
| `maintenance` | `error` | 故障 | 🔴 | 淺紅色 (#f8d7da) |
| `missing` | `error` | 故障 | 🔴 | 淺紅色 (#f8d7da) |
| `error` | `error` | 故障 | 🔴 | 淺紅色 (#f8d7da) |
| `unknown` | `offline` | 離線 | ⚪ | 淺灰色 (#e2e3e5) |

**映射程式碼位置**：

1. **狀態分組**（`show_machine_overview`，第 70-83 行）：
```python
for machine in valid_machines:
    status = machine.get('status', 'offline').lower()
    # 處理舊狀態的映射
    if status == 'maintenance' or status == 'missing':
        status = 'error'  # 失去心跳歸為故障

        status = 'offline'

    else:
        status_groups['offline'].append(machine)
```

2. **狀態統計**（`machine_status_page`，第 446-465 行）：

### 3. 錯誤碼處理

#### 3.1 後端錯誤碼定義

根據 `utils.py` 第 492-560 行的 `send_machine_status_event` 方法：

**狀態事件碼（fault_code）**：
- `0`: 機台 Alive 訊號
- `1`: 機台上線
- `9`: 機台下線
- `10-99`: 機台故障（錯誤碼）

**API 端點**：`POST /machines/{machine_code}/status-events`

**請求格式**：
```json
{
    "fault_code": 11,  // 錯誤碼（10-99 表示故障）
    "message": "機台故障描述",
    "timestamp": "2024-01-01T12:00:00Z",
    "metadata": {...}
}
```

#### 3.2 前台狀態更新

**位置**：`utils.py` 第 562-620 行，`update_machine_status_by_code()`

**狀態字串 → 錯誤碼映射**：
```python
def update_machine_status_by_code(self, machine_code: str, status: str, message: str = None):
    # 狀態字串到錯誤碼的映射
    status_to_fault_code = {
        "online": 1,      # 上線
        "offline": 9,     # 下線
        "missing": 11,    # 失去心跳（錯誤碼 11）
        "error": 11,      # 故障（錯誤碼 11）
        "fault": 11,      # 故障（錯誤碼 11）
        "maintenance": 11 # 維護/故障（錯誤碼 11）
    }
    
    fault_code = status_to_fault_code.get(status, 9)  # 預設為下線
    return self.send_machine_status_event(machine_code, fault_code, message)
```

**重點**：當狀態為 `missing`、`error`、`fault`、`maintenance` 時，都會映射為錯誤碼 `11`。

## 錯誤碼 11 的完整流程

### 當後端設定錯誤碼為 11 時：

1. **後端處理**：
   - 後端接收狀態事件：`POST /machines/{machine_code}/status-events`
   - `fault_code: 11` 表示機台故障
   - 後端更新機台狀態為 `maintenance` 或 `error`

2. **前台獲取**：
   - 前台呼叫 `GET /machines`
   - API 返回機台列表，其中 `status` 欄位為 `"maintenance"` 或 `"error"`

3. **前台映射**：
   - `maintenance` → `error`（故障）
   - `error` → `error`（故障）
   - `missing` → `error`（故障）

4. **前台顯示**：
   - 狀態統計：計入「🔴 故障」
   - 機台卡片：紅色背景（`#f8d7da`），紅色邊框（`#dc3545`）
   - 狀態文字：顯示「🔴 故障」
   - 操作按鈕：顯示「✅ 恢復上線」

## 注意事項

1. **狀態一致性**：所有錯誤相關狀態（`error`, `maintenance`, `missing`）都會統一顯示為「故障」
2. **錯誤碼範圍**：錯誤碼 10-99 都表示故障，前台統一處理
3. **預設行為**：如果狀態不在預期範圍內，會歸類為「離線」
4. **API 相容性**：支援分頁格式和直接列表格式的 API 回應
