## 🔄 切換到真實數據的準備工作

### ✅ 階段一：確認後端API支援 - 已完成！

**🎉 好消息：後端已有可用的 API！**

後端提供了 `GET /api/v1/ai/transactional-data` API，完全可以滿足需求！

#### 可用的 API 端點
```python
# ✅ 已確認可用
st.session_state.api.get_transactional_data(start_date_str, end_date_str, limit=1000)
```

**API 提供的響應格式**:
```json
{
  "data": [
    {
      "transaction_id": "T6678-5",
      "machine_id": "5",
      "purchase_timestamp": "2025-11-04T02:50:40.753148",
      "context": {
        "weather": "晴",
        "temperature_celsius": 22.6,
        "humidity": 65.0,
        "hour_of_day": 2
      },
      "transaction_details": [
        {
          "meal_id": "A013",
          "quantity_sold": 1,
          "unit_price": 125.0
        }
      ]
    }
  ],
  "pagination": {
    "total_records": 100,
    "current_page": 1
  }
}
```

✅ **評估結果**: 此 API **完全可用**！包含所有需要的欄位。

⚠️ **需要注意**:
- `meal_id` 需要映射到商品名稱（可從菜單API查詢）
- 缺少 `payment_method`（可預設為 'unknown'）
- 缺少 `status`（可預設為 'completed'）

📖 **詳細整合方案**: 請參考 `API整合方案.md`

## 📊 數據量估計

### 當前模擬數據規模
- **14天數據**
- **平均每日**: 25-40筆訂單（平日）/ 10-20筆（週末）
- **總訂單數**: 約350-500筆
- **總訂單項目數**: 約450-700項（每筆訂單1-3項商品）

### 生產環境建議
- **資料庫索引**: 
  - `created_at` (時間範圍查詢)
  - `machine_id` (機台篩選)
  - `status` (狀態篩選)
- **分頁**: 建議每頁100-200筆
- **快取**: 考慮快取當日/本週統計數據

## ⚠️ 注意事項

### 1. 數據一致性
- Dashboard 和 Sales Analytics 應該使用相同的數據源
- 統計數字應該保持一致

### 2. 效能考量
- 大量歷史數據可能需要分頁或聚合查詢
- 考慮使用後端預先計算的統計數據

### 3. 錯誤處理
- 已實現完整的錯誤處理機制
- API不可用時會顯示友好提示訊息
- 可考慮保留模擬數據作為後備展示

### 4. 時區處理
- 確保前後端時區一致
- 日期範圍查詢需要注意時區轉換
