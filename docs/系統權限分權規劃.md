# 系統權限分權規劃

## 📋 概述

本系統採用**雙角色權限模型**，分為**管理員**和**一般使用者**兩種角色。權限控制同時在前端（UI層）和後端（API層）進行驗證，確保系統安全性。

## 👥 角色定義

### 1. 管理員 (Admin)
- **標識**：`is_admin = True`
- **權限等級**：最高權限
- **功能範圍**：可訪問所有系統功能，包括管理功能和查看功能

### 2. 一般使用者 (Regular User)
- **標識**：`is_admin = False`
- **權限等級**：基礎權限
- **功能範圍**：僅可訪問查看類功能，無法進行管理操作

## 🔐 權限驗證機制

### 前端驗證
- **檢查方式**：`st.session_state.get('is_admin', False)`
- **驗證位置**：各功能模組入口處
- **錯誤提示**：顯示「❌ 權限不足：此功能僅限管理員使用」

### 後端驗證
- **認證方式**：Bearer Token (JWT)
- **驗證位置**：所有 API 端點
- **錯誤回應**：HTTP 401/403 狀態碼

## 🔄 權限檢查流程

### 前端權限檢查流程
```
使用者訪問功能
    ↓
檢查 session_state.is_admin
    ↓
是管理員？
    ├─ 是 → 顯示完整功能
    └─ 否 → 顯示錯誤訊息並返回
```

### 後端權限檢查流程
```
API 請求到達
    ↓
驗證 Bearer Token
    ↓
解析使用者資訊（包含 is_admin）
    ↓
檢查端點權限要求
    ↓
權限符合？
    ├─ 是 → 執行操作並返回結果
    └─ 否 → 返回 401/403 錯誤
```

## 🚨 權限錯誤處理

### 前端錯誤處理
- **錯誤訊息**：「❌ 權限不足：此功能僅限管理員使用」
- **行為**：阻止功能執行，顯示錯誤訊息
- **日誌記錄**：記錄未授權訪問嘗試

### 後端錯誤處理
- **HTTP 狀態碼**：
  - `401 Unauthorized`：未認證或 Token 無效
  - `403 Forbidden`：已認證但權限不足
- **錯誤訊息**：返回詳細的錯誤描述
- **日誌記錄**：記錄所有權限驗證失敗的請求

## 🔐 使用者註冊與角色分配

### 註冊流程
1. 使用者填寫註冊表單
2. 選擇使用者類型（一般使用者/管理員）
3. 系統創建帳號並設定 `is_admin` 標記
4. 註冊成功後可使用對應權限

### 角色變更
- 目前系統不支援使用者自行變更角色
- 角色變更需要透過管理員在使用者管理中修改

## 📌 權限設計原則

1. **最小權限原則**：預設為一般使用者權限，僅授予必要權限
2. **雙重驗證**：前端和後端同時進行權限檢查
3. **明確錯誤提示**：權限不足時提供清晰的錯誤訊息
4. **日誌記錄**：記錄所有權限相關的操作和錯誤
5. **功能隔離**：管理功能與查看功能明確分離
